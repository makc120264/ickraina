# Завдання 3. JS-інтерфейс без фреймворків

Створіть просту HTML-сторінку з базовим інтерфейсом, яка працює з вашим API з Завдання 1.

### Вимоги:
- Завантаження списку замовлень через fetch() після завантаження сторінки.
- Форма створення нового замовлення з полями (наприклад, ім’я, ціна, статус).
- Після сабміту — асинхронне створення замовлення без перезавантаження.
- Повідомлення про результат виводяться не через alert() чи console.log(), а через ваш елемент на сторінці (наприклад, блок з текстом).

### Додатково:
- код має бути структурований і зрозумілий
- використовуються лише нативні можливості JS (без jQuery, Vue тощо)

# Реалізація:
Це проста веб-сторінка `/orders`, яка через нативний `fetch()` спілкується з API замовлень.
При відкритті сторінки список замовлень завантажується автоматично, а новий запис створюється асинхронно
сабміту форми - без перезавантаження.
Усі повідомлення про успіх/помилки виводяться у спеціальному блоці на сторінці.

## Що де розташовано
- Роут сторінки: `GET /orders` (файл `routes/web.php`) - повертає виставу `resources/views/orders.blade.php`.
- API (файл `routes/api.php`):
  - `POST /api/orders` - створити замовлення;
  - `PATCH /api/orders/{order}/status` – змінити статус замовлення;
  - `GET /api/orders` - список замовлень (фільтрація та опціональна пагінація).
- Контролер API: `App\Http\Controllers\OrderController`.
- Модель: `App\Models\Order`.
- Проста API-авторизація: middleware `ApiAuth` - перевіряє заголовок `X-API-KEY`.
- Єдиний формат відповідей: `App\Http\Responses\ApiResponse`.

## Як працює сторінка `/orders`
1. Під час завантаження HTML вставляє мета-тег з ключем API:
   - `<meta name="api-key" content="{{ env('API_KEY', 'secret123') }}">`
   - Звідси JS бере значення для заголовка `X-API-KEY`.
2. Після завантаження документ викликає `loadOrders()`:
   - `GET /api/orders?paginate=false`
   - Заголовки: `X-API-KEY: <ваш_ключ>`
   - отримані елементи (`data.payload.items`) рендеруються до списку; якщо порожньо – показ «Замовлення відсутні».
3. Форма «Створити замовлення» надсилає дані без перезавантаження:
   - Валідація ціни в браузері (число ≥ 0), потім `fetch()` на `POST /api/orders` з тілом `{"price":..., "status":...}`.
   - Обов'язкові заголовки: `Content-Type: application/json`, `Accept: application/json`, `X-API-KEY: ...`.
   - У разі успіху: повідомлення про успіх, очищення форми, повторне завантаження списку.
   - При помилці: повідомлення з текстом з API та деталями валідації, якщо є.
4. Повідомлення:
   - Вставляються в блок `#messages` як Bootstrap‑alert, без `alert()`/`console.log()`.

## Вимоги до оточення
- В `.env` повинен бути заданий `API_KEY` (або використовується дефолт `secret123`). 
  - Приклад: `API_KEY=secret123`
- Роути API працюють під групою `api` та middleware `api.auth` (див. `bootstrap/app.php` та `routes/api.php`).
- База даних налаштована для моделі `Order` (міграції/таблиця з колонками хоча б `id`, `status`, `price`, `created_at`, `updated_at`).

## Як користуватися
1. Переконайтеся, що бекенд запущений (наприклад, php artisan serve) і доступний за доменом проекту.
2. В `.env` задайте `API_KEY` і перезапустіть програму, якщо потрібно.
3. Відкрийте у браузері `/orders`:
   - Список підвантажиться автоматично.
   - Введіть ціну та виберіть статус, натисніть "Створити" - замовлення створиться без перезавантаження, список оновиться.

## Формат запитів до API
- Список без пагінації:
  - `GET /api/orders?paginate=false`
  - Заголовок: `X-API-KEY: <ключ>`
- Створити замовлення:
  - `POST /api/orders`
  - Заголовки: `Content-Type: application/json`, `X-API-KEY: <ключ>`
  - Тіло: `{"price": 100.5, "status": "new"}` (статус опціональний, за замовчуванням `new`)
- Оновити статус:
  - `PATCH /api/orders/{id}/status`
  - Тіло: `{"status": "processing"}`

## Обробка помилок
- Якщо `X-API-KEY` відсутній/невірний – `401 Unauthorized` з повідомленням `Invalid or missing API key`.
- Помилки валідації при створенні/оновленні - `422` з `payload.errors` (наприклад, `price` має бути числом ≥ 0,
  'status' - один з: 'new', 'processing', 'completed', 'cancelled').
- Мережні помилки та не-OK відповіді на сторінці відображаються у блоці повідомлень.

## Де правити поведінку
- Відображення та логіка сторінки: `resources/views/orders.blade.php` (IIFE з функціями `showMessage`, `renderOrders`, `loadOrders`, `createOrder`).
- Бізнес-правила API: `OrderController`.
- Авторизація по API-ключу: `App\Http\Middleware\ApiAuth`.
